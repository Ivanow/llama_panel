# Паспорт файла: `manager.sh`

**Путь:** `llama_server/manager.sh`
**Роль:** Оркестратор процессов.

## 1. Контракты (Что гарантирует скрипт)
1.  **Изоляция:** Процессы не конфликтуют, у каждого свой порт и имя tmux-сессии (`llama-<name>`).
2.  **Отказоустойчивость:** Если модель падает при загрузке (битый файл, OOM), скрипт обнаруживает это в течение 120 секунд и выводит причину.
3.  **Синтаксическая безопасность:** Конфиги проверяются через `bash -n` перед запуском.

## 2. Алгоритм действия `start`
1.  Проверить существование файла `instances/$INSTANCE.conf`.
2.  Проверить валидность bash-синтаксиса: `bash -n $CONF`.
3.  Загрузить переменные (`source $CONF`).
4.  **Проверка tmux:** Если сессия `llama-$INSTANCE` уже существует — выйти (модель уже работает).
5.  **Проверка портов:** Выполнить `ss -tulpn | grep ":$PORT "`. Если порт занят — выйти с ошибкой.
6.  Запустить tmux в фоне:
    `tmux new-session -d -s "llama-$INSTANCE" "$BIN --model $MODEL --port $PORT ... > $LOG 2>&1"`
7.  **Healthcheck:** Запустить цикл на 60 итераций (по 2 сек):
    *   Стучимся `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:$PORT/health`
    *   Если `200` — успех.
    *   Если tmux-сессия исчезла (процесс упал) — вывести `tail -n 20 $LOG` и выйти с ошибкой.
    *   Если прошло 120 секунд — таймаут.

## 3. Обработка ошибок
*   **Нет конфига:** `ОШИБКА: Конфиг не найден!`
*   **Синтаксическая ошибка в конфиге:** `ОШИБКА: Обнаружена синтаксическая ошибка!`
*   **Порт занят:** `ОШИБКА: Порт $PORT занят!`
*   **Падение при загрузке:** Скрипт выведет последние 20 строк лога.

## 4. Что модуль НЕ делает
*   Не управляет сборкой `llama.cpp` (ожидает готовый бинарник).
*   Не проверяет свободную память (это делает Python-бэкенд).
*   Не знает о существовании Flask.
