# Паспорт файла: `app.py`

**Путь:** `llama_server/web_panel/app.py`
**Роль:** REST API, бизнес-логика, валидация, расчет ресурсов.

## 1. Алгоритм `get_instances` (Двухпроходный парсинг)
Этот метод решает задачу: "Нельзя запустить модель, если не хватает памяти или порт занят".
1.  **Проход 1 (Сбор данных):**
    *   Сканируем папку `instances/*.conf`.
    *   Для каждого файла парсим `PORT` и `MODEL` (регулярками).
    *   Выполняем `tmux has-session -t llama-<name>` чтобы узнать, запущен ли сервер.
    *   Если запущен — добавляем его порт в список `running_ports`.
2.  **Проход 2 (Расчет ресурсов):**
    *   Получаем `free_vram` (через `nvidia-smi`) и `free_ram` (через `/proc/meminfo`).
    *   Для каждого **выключенного** конфига:
        *   Если его порт есть в `running_ports` — блокируем (`can_start = false`).
        *   Иначе считаем память: `size_mb = os.path.getsize(model)`.
        *   `vram_needed = size_mb * (gpu_layers / 99.0) + 500`
        *   `ram_needed = size_mb * ((99 - gpu_layers) / 99.0) + 1000`
        *   Если `free_vram < vram_needed` или `free_ram < ram_needed` — блокируем.

## 2. Алгоритм `create_instance` (Безопасность)
1.  Проверка `re.match(r'^[a-zA-Z0-9_-]+$', name)`.
2.  Проверка порта (`1024 <= port <= 65535`).
3.  **Защита от инъекций:** Экранирование аргументов через `shlex.quote(model)` и `shlex.quote(args)`. Это гарантирует, что если в аргументах встретятся кавычки (например, `--chat-template-kwargs '{"a": 1}'`), они не сломают bash-скрипт.
4.  Проверка, что такой порт не занят другим `.conf`.
5.  Запись файла.

## 3. Кэширование моделей (Модели не каждый день качаем)
*   `scan_models_to_cache()`: Рекурсивно обходит `/stor001/models` (до 6 уровней вглубь). Найденные `.gguf` сохраняет в `models_cache.json`.
*   **Атомарная запись:** Сначала пишет в `models_cache.tmp`, затем вызывает `os.replace()`. Это защищает от чтения битого JSON, если пользователь нажмет "Обновить" во время чтения.
